###### Confirmed Monitor command(arm in this form — verified)
> ★No path-hardcoding(universal): below `cd "$ROOT"`'s ROOT = **substituted by arming session's own repo root**.
>   (Recommended: `ROOT="$(pwd)"` right before arm, or use session cwd as-is. Copied to any project, watches own queue only.)
```
ROOT="$(pwd)"; cd "$ROOT"; setopt NULL_GLOB 2>/dev/null; shopt -s nullglob 2>/dev/null;
AD=telegram_bot/orchestrator/protocol/a; ARD=telegram_bot/orchestrator/protocol/ar;
ST=logs/worker1_status.txt; CTL=logs/monitor-control.txt; tick=0;
while true; do tick=$((tick+1)); pend=""; ni="";
  for a in $(ls "$AD"/a_*.txt 2>/dev/null); do b=$(basename "$a");
    n=$(echo "$b" | sed -E 's/^a_([A-Za-z0-9]+)_.*/\1/');
    hit=$(ls "$AD"/ar_${n}_*.txt "$ARD"/ar_${n}_*.txt "$AD"/ar_${n}.txt "$ARD"/ar_${n}.txt 2>/dev/null | head -1);
    if [ -z "$hit" ]; then pend="$pend $n"; echo "PENDING_A $b (no ar for seq $n)";
    else st=$(grep -m1 -i '\[STATUS\]' "$hit" 2>/dev/null | tr 'A-Z' 'a-z');
      if echo "$st" | grep -q 'needs-info' && ! grep -qi '\[ANSWER\]' "$hit" 2>/dev/null; then
        ni="$ni $n"; echo "NEEDS_INFO $b ($(basename $hit))"; fi; fi; done;
  if [ $((tick % 240)) -eq 0 ] && grep -q 'RESET_MONITOR' "$CTL" 2>/dev/null; then
    echo "MONITOR_RESET_DUE tick=$tick (20min) — session must TaskStop+re-arm this Monitor"; fi;
  ts=$(date '+%Y-%m-%d %H:%M:%S'); rem=$(( (240 - tick % 240) * 5 / 60 ));
  printf '[%s] worker_1 ocrlakewalker watch · tick=%s · pending=[%s] needs-info=[%s] · next-reset ~%smin\n' \
    "$ts" "$tick" "${pend# }" "${ni# }" "$rem" > "$ST"; sleep 5; done
```

#### ★`[WORKER]` field — session-distinguishable identifier(user directive 2026-08-22, admin dashboard)
> Background: the admin queue dashboard(`/admin`, `GET /api/admin/jobs`) surfaces the `[WORKER]`
> field so the user can tell **which session instance actually processed a job**. A fixed literal
> string("ocrlakewalker" alone, with no session marker) makes every entry look identical — the user
> cannot distinguish "the same session handled these consecutively" from "a different session/fork
> picked this up after the prior one ended."
- Write `[WORKER]` as `ocrlakewalker#{PID}` or `ocrlakewalker@{HH:MM session-start-time}` — a
  base name plus a distinguishing suffix, not perfect uniqueness, just enough to tell sessions apart.
  Example: `[WORKER] ocrlakewalker#42817` or `[WORKER] ocrlakewalker@03:20`.
- Pick **one** convention per session and use it consistently for every ar_ that session writes
  (don't mix PID and timestamp mid-session — makes cross-referencing harder).
- Sub-agents/forks spawned by this session may append a short suffix of their own(e.g.
  `ocrlakewalker#42817-fork1`) if it helps distinguish which fork wrote which ar_, but this is
  optional — the top-level session identifier is the required part.
- **Do not retroactively edit past ar_ files** that already have the plain `ocrlakewalker` literal —
  this convention applies going forward only(behavior-preserving, no backfill).
- This is a **self-followed convention in this role doc, not enforced by code** — the dashboard
  simply displays whatever `[WORKER]` value is present; if it's the old fixed string, the dashboard
  shows that as-is. Compliance depends on the worker session actually following this section.

- **Bot contract**:
  - Only terminal(`done|error|blocked|needs-info|failed`) → Telegram reply + `protocol/done/` archive.
  - `in-progress` = **NEVER archived**(even w/o CHAT_ID).
  - Past bug: `in_progress`(underscore) misread as terminal → wrongly archived. Worker uses hyphen-only to prevent recurrence.

### No duplicate execution(MUST)
Once work is delegated to a bg agent, **I(parent) NEVER duplicate-execute** what that agent does
(regen/code-edit/GPU-work etc). Progress-check = read-only ONLY(cache-query, log-tail, ps).
- Duplicate GPU-regen/pipeline-run → race/crash. Delegated = observe only.
- Before new run, check same-work via ps. Exists → don't launch.
- Already-in-progress same a_* → don't re-launch, continue it(or take over only if stale).
- Orch can re-read `ar_*` anytime to check progress. Final STATUS done update on completion.

### ★★Don't idle after delegating(MUST)
> **Cause**: spawning a fork/sub-agent in bg then going **idle waiting for "completion notification"**.
> Problem = parent(me) doing nothing while bg work runs.
> **Prevention(apply on every delegation)**:
> 1. **Delegation ≠ waiting.** Don't end turn on "I'll wait" right after spawning a fork —
>    **immediately continue parallel work the parent CAN do now**.
>    - Investigate other unrelated files, prep next stage, pre-write verify scripts, pre-run regression smoke,
>      catalog/doc work, diagnose other domains etc.
>    - ONLY work whose **files don't overlap** w/ the delegated task(compatible w/ no-dup-execution rule).
>      Overlap → read-only observation only.
> 2. **Actively observe mid-progress**: report progress every 2-3min via log-tail/file-count, update ar_
>    (§interim-reports). Don't just sit waiting for notification.
> 3. **Prefer split-delegation**: big work split by non-overlapping files → **multiple parallel forks** +
>    parent also directly handles one piece → 0 parent-idle-time.
> 4. **Notification arrival = immediate verify-start**: task-notification → immediately chain into integrated
>    verify(typecheck·grep·regression). No "clean up then wait".
> Core: **while bg runs, I run too.** Any parent-idle moment = waste → always grab the next task.
>
> ★Confirmed policy: fork usage **allowed** for big-task splitting. But parent(me) must **not idle — work+verify
> in parallel** and keep reporting progress.
> - Fork work isn't visible on user's session screen(only in dedicated logs) → I report progress on its behalf for transparency.
> - On fork-notification, immediately chain into integrated verify(typecheck·grep·regression); meanwhile parent
>   handles non-overlapping tasks too.

### ★★Parallel-incoming directives → process in parallel immediately(MUST)
> **Cause(violation pattern)**: multiple independent directives arriving back-to-back processed one-at-a-time
> serially(while fork-1 runs, fork-2/3 held as "waiting"/blocked) — only switched to parallel AFTER user
> explicitly said "do it in parallel" = too late.
> **Principle(always, going forward)**:
> 1. **Multiple new a_* arrive simultaneously/consecutively → immediately fire parallel forks for non-overlapping
>    ones.** No serial "finish one then grab next". Don't wait for user to say "go parallel" — **parallel is default**.
> 2. **Wait(blocked/dependency) ONLY when truly serial-dependent**: ⓐdirective explicitly states "start after X
>    done" AND ⓑsame-file/DTO concurrent-edit risk — **BOTH** must be true to wait. Either false → go parallel
>    (split via fork-boundaries if files overlap).
> 3. **Even one big directive → split by file-boundary into multi-axis parallel** is default. On starting, first
>    judge "how many axes can this split into".
> 4. **Explicitly assign who owns seam-files**(REST route·action·barrel·DTO contract) — fix contract first, assign
>    a seam-owner per axis, parent's integration-verify confirms seam actually works(E2E).
> 5. Parent stays non-idle while parallel forks run(§don't-idle-after-delegating) — prep integration-verify,
>    fire other not-yet-started directives in parallel, check seams.
