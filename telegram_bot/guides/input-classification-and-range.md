# 입력값 분류·범위·코드 표준 (범용 — 모든 프로젝트 무조건 반영)

> "인간 세상의 룰": 사람이 실제로 쓰는 서비스라면 **분류는 정해진 목록에서 고르게, 범위는 하한~상한을
> 지정하게** 돼 있어야 한다. 이게 없으면 정산·검색·통계·가입이 제대로 될 수 없다.
> 근거: 유저 지시 2026-08-02(성별·회원유형 누락, 기간 하드코딩, 금액범위 부재 → 근본은 표준 부재).

이 규칙은 봇이 지시하는 **모든 프로젝트**의 폼·필터·조회 화면에 적용. 프로젝트의 네이밍 표준과 연계.

---

## 1. ★ 판별 규칙 — "이 값이 분류값인가 범위값인가" (핵심)

새 필드를 만들 때 **먼저 성격을 판별**한다. 판별 못 하면 또 제각각이 된다.

| 성격 | 판별 질문 | 신호(예: 한국 행안부 표준 접미사) | 입력 UI | 저장 |
|------|-----------|-----------------------------------|---------|------|
| **① 분류값(코드)** | 정해진 유한 목록에서 하나/여럿 고르는가? | `_SE_CD`(구분코드)·`_CD`·`_STTS_CD` | 코드기반 Select/Radio/다중선택 | 코드값 |
| **② 범위값(연속)** | 연속량을 하한~상한으로 거르는가? | `_YMD`/`_DE`(일자)·`_TM`·`_DT`·`_AMT`(금액)·`_CO`(개수)·`_SCORE` | DateRangePicker·RangeInput(min~max) | from/to·min/max |
| **③ 불리언** | 예/아니오 2값? | `_YN` | Switch/Checkbox | 'Y'/'N' |
| **④ 자유값** | 목록도 범위도 아닌 임의 입력? | `_NM`(명)·`_CN`(내용)·`_ADRES` | text/textarea | 문자열 |

**철칙**:
- 접미사가 구분/상태 코드(`_SE_CD`/`_CD`/`_STTS_CD`) → **무조건 분류값** → 공통코드 사전에 등재 + 코드기반 Select/Radio. `<option>`·라벨 하드코딩 금지.
- 금액·일자·개수·점수를 **"범위로 거른다"** → 범위 컴포넌트(from~to, min~max). **기준일·상수 하드코딩 금지.**
- 조회/필터의 분류값은 보통 **다중선택 허용**("이 조건에 여러 값이 동시에 참일 수 있나?" → 예면 다중).

> 프로젝트가 다른 네이밍 체계를 쓰면(예: camelCase enum), 접미사 대신 **"값 집합이 유한·고정인가(→분류)
> vs 연속량인가(→범위)"** 라는 본질 질문으로 판별한다. 신호는 언어가 달라도 원칙은 같다.

## 2. 흔한 누락 (인간 세상의 룰 — 반드시 확인)

사람이 쓰는 서비스라면 당연한데 LLM이 자주 빼먹는 것:
- **성별** 선택 (분류값: 남/여/기타·응답거부 등 정책에 맞게).
- **회원유형/역할** 선택 (일반 이용자 / 서비스 제공자 / … — 가입 진입에서 반드시).
- **기간 조회**: 프리셋(오늘/이번주/이번달/분기/년)"과 함께" **사용자지정 from~to·년월일** 선택.
- **금액·수치 범위**: min~max 필터(정산·검색·통계).
- **다중선택**: 직군·지역·상태를 여러 개 동시 필터.
- **지역**: 광역→기초 계층 선택(단순 텍스트 매칭 금지).

이 목록에 해당하는 화면을 만들 때, 위가 **빠지지 않았는지** 완료 전 체크한다.

## 3. 표준 컴포넌트 (프로젝트에 신설/재사용)

| 컴포넌트 | 책임 |
|----------|------|
| **CodeSelect / CodeRadio / CodeMultiSelect** | 공통코드 사전 기반 선택. 하드코딩 option 대체 |
| **DateRangePicker** | 프리셋 + **사용자지정 from~to** + 년/월/일. 기준일 하드코딩 금지. URL 동기화 |
| **RangeInput** | 숫자 min~max(금액·평점·연차), min≤max 검증 |
| **RegionPicker(지역이 있으면)** | 광역→기초 계층·다중선택 |
| **FilterBar / DataView 확장** | 위를 조합, URL 쿼리 동기화, **서버쿼리로 필터**(메모리 filter 금지) |

## 4. 공통코드 사전 (분류값 단일 출처)

- 모든 분류값(코드)을 **한 곳**(예: `lib/codes`)에 `{ group, code, label, order, meta }` 로 정의.
- 폼·필터·배지·표시는 **사전만 참조**. 화면 하드코딩 option/라벨 금지, 중복 정의 0.
- 프로젝트의 네이밍/용어 표준과 연계(미등록 신조어는 예외신청 절차로 등재).

## 5. DAL/API 계약

- 범위: `from`/`to`, `min*`/`max*`. 다중: `key=A,B` 또는 `in[]`. 페이지 size 상한.
- **서버 쿼리로 필터**(DB where). 메모리 filter·기준일 하드코딩 금지. 정렬·envelope 표준.

## 6. 완료조건 (워커 지시서에 인용)

1. 새 필드는 **§1 판별 먼저** → 성격에 맞는 컴포넌트/저장. 판별 결과를 지시서/PR에 명시.
2. 분류값은 코드사전만(하드코딩 금지). 범위는 표준 컴포넌트만(하드코딩 기준일 금지).
3. §2 인간 세상의 룰 누락 체크(성별·회원유형·기간범위·금액범위·다중선택·지역계층).
4. 서버쿼리 필터·URL 동기화·다중선택·접근성(라벨·키보드·aria)·디자인 토큰 동반.
