# 공용 개발 가이드 — "인간 세상의 룰" (모든 프로젝트 무조건 반영)

> 유저 지시 2026-08-02: **"우리 에이전트에는 인간 세상의 룰이 들어가야 한다."**
> "이런 정리(입력 분류·범위 표준 등)는 다른 프로젝트에도 무조건 반영돼야 하는 규칙이니 봇 디렉토리에 가이드로."

## 왜 이게 필요한가 (배경)
LLM 워커는 **현실 세계에서 당연한 규칙**을 자주 빼먹는다. 실제 사고 예:
- 회원가입에 **성별·회원유형(이용자/제공자) 선택이 없음** → 제공자로 가입할 방법이 없었다.
- 정산·통계 **기간 조회에 년월일·범위(from~to) 선택이 안 됨**(기준일 하드코딩).
- 금액 **범위(min~max) 필터가 아예 없음** → 정산·검색이 제대로 될 리 없다.

이건 "리서치 실패"이자 **상식(인간 세상의 룰)의 부재**다. 기능이 돌아가도 사람이 실제로 못 쓴다.

## 목적
이 `guides/` 는 **프로젝트 불문 범용 규칙 저장소**다. 텔레그램봇 오케스트레이터가 **어느 프로젝트에
지시(a_*)를 뿌리든, 이 가이드를 "무조건 준수 규칙"으로 워커 지시서에 주입**한다.
→ 워커가 상식(성별·범위·분류·접근성·보안 등)을 빼먹지 않도록 강제한다.

## 적용 방식 (오케스트레이터)
- 워커 지시서(a_*) 생성 시, 해당 작업에 관련된 guides 규칙을 **완료조건**으로 인용/링크한다.
- 프로젝트별 `.claude/rules/`(그 프로젝트 전용)와 **함께** 적용. guides = 범용, .claude/rules = 프로젝트 특화.
- 새 규칙은 "특정 프로젝트에서 배웠지만 어디서나 통하는가?"를 기준으로 이곳에 승격.

## 규칙 목록
- [input-classification-and-range.md](./input-classification-and-range.md) — ★ 입력값 성격 판별(분류값/범위값/불리언/자유값) + 공통코드 사전 + 기간·금액 범위·다중선택 표준 컴포넌트. "무엇이 분류값이고 무엇이 범위값인지 어떻게 아느냐"의 판별 규칙 포함.
- [flow-and-data-handoff.md](./flow-and-data-handoff.md) — ★ 업무(플로우) 관점 설계 + 화면 간 데이터 전달(반쪽 연결 금지: 선택→다음화면 반영) + 선택화면에 대상 상세 + 목록·이력은 최근 N건+마스킹. "각 업무 입장에서 설계"·"예약 클릭했는데 예약자 선택 안 됨" 대응.

## 앞으로 추가될 "인간 세상의 룰" 후보
- 회원가입/온보딩 필수요소(성별·연령·회원유형·약관·본인확인)의 상식 체크리스트.
- 목록/조회 화면의 당연한 것(정렬·페이징·빈상태·건수·필터가 실제로 동작).
- 금액·날짜·전화·주소 등 현실 데이터의 포맷·검증·표시 상식.
- 접근성·보안·개인정보(민감정보 노출 금지)의 최소 상식선.
